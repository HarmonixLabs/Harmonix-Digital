1. Agent Builder UI/UX Design

The Agent Builder features a split-pane design: a left panel for configuring the agent and a right panel showing a live visual flow diagram.  In the left pane, users enter a natural-language prompt or select from use-case templates, then fill in agent metadata (name, description, tags, avatar, license type), choose integration hooks (e.g. Zapier, Notion, Slack), and define trigger types (API call, scheduled job, webhook, chat command, CRM event).  In the right pane, a flow canvas displays the agent’s logic as connected nodes (steps, API calls, branches).  Users can click any node to edit its behavior or add conditions.  A toggle switches between Flow View and Chat Simulation View for quick testing.  Below, a sandbox console lets the user input test commands and see real-time execution logs (API responses, NLP outputs, decision paths).

This drag-and-drop, visual workflow approach lets non-technical users build complex logic without code .  It follows dashboard design best practices: clear goals, user-friendly layouts, and progressive disclosure of advanced settings .  The interface should use familiar UI patterns (form fields, dropdowns, graphical flows) so users can build automation by iterating on simple wireframes and seeing instant feedback  .

2. Deployment Pipeline & Blockchain Minting

Once an agent is ready, the Deploy button triggers the full deployment pipeline. The platform: (1) saves the agent’s JSON config and flow definition to the backend; (2) deploys the agent instance into the user’s live Harmony dashboard; and (3) mints an ERC-721 NFT on the Polygon blockchain representing the agent’s license.  This NFT includes metadata fields such as name, description, image, plus custom traits like agent_id, creator_wallet, functions, license_type, created_at, updated_at, usage_count, and any relevant categories. For example, a sample metadata JSON might look like:

{
  "name": "Echo AI Agent",
  "description": "An AI assistant that drafts marketing content on demand.",
  "image": "ipfs://Qm.../echo-avatar.png",
  "attributes": [
    {"trait_type": "Agent ID",       "value": "agent_12345"},
    {"trait_type": "Creator Wallet", "value": "0xABCD..."},
    {"trait_type": "Functions",      "value": "draft_content, edit_posts"},
    {"trait_type": "License Type",   "value": "subscription"},
    {"trait_type": "Created At",     "value": "2025-07-05T00:00:00Z"},
    {"trait_type": "Updated At",     "value": "2025-07-05T12:37:00Z"},
    {"trait_type": "Usage Count",    "value": 0},
    {"trait_type": "Categories",     "value": "marketing, content"}
  ]
}

This follows the ERC-721 metadata standard: every NFT has a unique tokenId and metadata JSON (e.g. with name, description, image, attributes) that OpenSea and wallets can read  .  Here the agent’s name, description, and image are top-level fields, and the other details are encoded as custom attributes. (OpenSea’s example metadata shows how name, description, image, and attributes are used .) The NFT is minted to the user’s connected wallet; this proves ownership/license and enables resale if applicable.  The platform also registers the new agent in the Harmony Brain registry, allowing smart routing and discovery in the marketplace.

The Harmony marketplace lists all 12 core agents. Four “unlocked” demo agents (Cash, Echo, Flow, Sol) are available to anyone (even visitors) for free trial.  The other 8 agents are locked behind signup.  On the public demo page, visitors can talk to Sol (the strategic QA agent) in a chat interface; Sol analyzes their needs and recommends three best-fit agents.  Visitors can then test the four free demo agents in sandbox mode (e.g. Cash to book a call, Echo to draft content, Flow to analyze SOPs, Sol for strategy Q&A). Locked agents appear blurred with a message “Locked – sign up to unlock”.

Once a user signs up and connects their account, they are prompted to choose a plan: 1 agent, 3 agents, 6 agents, or full suite (9–12 agents).  On purchase, the chosen agents become available in the user’s Harmony Dashboard, deployed and linked to their tools (CRM, Slack, email, etc.) as needed.  The user can then interact with each agent via the dashboard (issuing commands, viewing logs, integrating with systems).  Each agent can also perform tasks on behalf of the user (e.g. send emails, create tickets) once given permission.

4. Payment & Billing Integration

The platform offers multiple payment methods: Stripe Checkout for credit/debit cards and wallets, Coinbase Commerce or Bridge for crypto (e.g. USDC/ETH), and the native HarmonyCoin token.  Through Stripe, we implement subscription and one-time payments using Stripe Billing (PaymentIntents/Checkout Sessions). A typical Stripe Checkout Session JSON (returned by the API) includes fields like id (session ID), payment_status (paid/unpaid), amount_total, currency, customer, and optional metadata for our record  . For example:

{
  "id": "cs_test_51HxyzABC123",
  "object": "checkout.session",
  "payment_status": "paid",
  "amount_total": 2999,
  "currency": "usd",
  "customer": "cus_ABC123",
  "metadata": {
    "user_id": "user_45678",
    "agent_id": "agent_12345"
  }
}

Stripe Elements/Checkout provides a seamless on-brand UI for cards. We use Stripe Customer objects to remember users and support one-click upgrades. For crypto, we integrate Coinbase Commerce (settling to USDC) or Stripe’s new crypto onramp. Coinbase Commerce lets customers pay in dozens of cryptocurrencies (BTC, ETH, USDC, etc.) while guaranteeing settlement in stablecoin . In fact, Stripe has partnered with Coinbase to add USDC on Base (Polygon’s L2) to its crypto payout and on-ramp products  . Thus customers can pay with crypto or fiat; Stripe/Bridge can accept stablecoins and settle in USD to our account, or directly send crypto payouts to user wallets.

All purchases (plan subscriptions or individual agents) are processed through 1-click checkout modals. For subscriptions, Stripe auto-renews monthly unless cancelled. Metadata on each transaction ties it to the user, agent, or plan for tracking. Webhooks keep the platform in sync (e.g. updating status after payment, sending email receipts). Users can pay in their preferred method (credit card, bank transfer, Coinbase wallet, or our HarmonyCoin token – using our own crypto would involve integrating Bridge or a custom token sale mechanism).

5. Creator Revenue & Payouts

Creators earn revenue on a 70/30 split (creator/Harmony) . For example, a $100 sale yields $70 to the creator. Using Stripe Connect, earnings are paid out to creators’ bank accounts or wallets automatically (Stripe Connect handles identity/KYC and routing) . Creators can choose pricing and license types (free, one-time license, per-use, or subscription). A creator dashboard shows monthly earnings, agent usage stats, and customer reviews/ratings. Payouts occur weekly via Stripe Connect transfers or crypto transfers, once users complete KYC/tax forms. The system sends alerts if payout fails or a minimum threshold is reached. This follows typical marketplace logic: Elgato’s Maker program, for example, uses Stripe Connect to disburse 70% of sales to makers’ accounts  .

6. Role-Based Access Control

The platform uses RBAC to manage permissions. Key roles include: Visitor (browse demos/marketplace, join waitlist), User (dashboard access, purchase agents), Team Member (end-user executing tasks, submitting approvals), Founder (organization admin for billing and settings), Creator (agent builder and publisher), and Admin (platform administrator with override rights). For example, an “Admin” role may grant full back-end control (approve listings, manage NFTs), whereas a “Creator” role can only access their own builder and stats . RBAC ensures users see only relevant views: admins see all transactions and logs, founders manage their org, users see deployable agents, etc. This follows standard SaaS patterns where roles map to permission sets (much like a Sales Rep vs Executive example in enterprise apps) .

7. AI Agent Recommendation (“Sol Brain”)

Harmony’s AI “Brain” (Sol) constantly analyzes the organization’s profile (industry, size, workflows) and usage patterns. It offers a “smart recommender” that suggests up to three agents to deploy next. For example, Sol might notice many customer inquiries go unanswered and recommend the “Flow” support agent. Users can one-click deploy recommended agents directly from the suggestion. If no off-the-shelf agent fits, Sol suggests “Build Your Own” – guiding the user to the Agent Builder to create a custom agent. In the demo sandbox, Sol can deploy temporary trial agents (limited to ~5 uses) so prospects can preview locked agents before signing up. This personalized recommendation increases engagement by matching tools to needs.
