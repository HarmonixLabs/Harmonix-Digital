Harmonix Ecosystem Sitemap & Platform Map

Figure: High-level sitemap of the Harmonix platform, showing public-facing pages (gray) and the private logged-in app (yellow). Arrows indicate typical user flows (e.g. Home → Demo/Waitlist → Login → Dashboard). Dashed lines show transitions like a waitlist user gaining access.

Public (Logged-Out) Pages and Access

Home (/) – Public Landing Site: The main marketing page for Harmonix, open to all visitors. It showcases the value proposition (“AI Agents & Automation Systems…”) with a bold, minimalist design (Deep Space Black background, gold accents) and clear calls-to-action ￼ ￼. Primary CTAs on the home page include “Book a Demo” (which opens a scheduling form) and “Meet the Agents” (which scrolls to an agent overview section) ￼. There is also a “Stay in the Loop” option that triggers a sign-up lightbox to capture the visitor’s email, industry, and team size ￼ – essentially a Join Waitlist form for those interested but not yet onboarded. This waitlist form is integrated with Harmonix’s CRM (GoHighLevel), so that every sign-up is tracked and tagged for follow-up nurturing ￼. Visitors can navigate basic sections (e.g. features, pricing, contact), but any attempt to access app functionality will route them to login or the waitlist/signup flow.
	•	Demo Page (/demo): A publicly accessible demo or teaser page. If the platform is in closed beta, this page might show an interactive preview or video of the Harmonix AI in action, and invite users to join the waitlist or request access. Logged-out users who try to use live features (like chatting with the AI) here will be gently prompted to log in or sign up. In practice, restricted pages redirect to the demo or waitlist – for example, if a guest manually visits /dashboard, they would be rerouted to /demo or a sign-up page with a message about requesting access. This ensures unauthorized users are never faced with a dead-end; they’re always offered a next step (demo or join). GHL tracking scripts are embedded here as well, so any “Request Access” or “Join Waitlist” clicks feed into the CRM pipeline for sales follow-up ￼.
	•	Marketplace (Browse) (/marketplace): The public marketplace listing of AI Agent Cards. Guests can browse and search the catalog of AI agents available – each agent is presented as a collectible card with an illustrated avatar, name, category (e.g. Sales, HR, etc.), and a unique “power” or function listed on the front ￼. Clicking on an agent shows more details (profile, what it can do, perhaps a back-of-card view with bio and NFT serial number/XP stats) ￼. Guests can explore these details freely to understand the offerings. However, purchasing or activating an agent requires login. If a guest tries to initiate a purchase or click a “Deploy/Buy” button, the site will prompt them to log in or create an account (and likely also to connect a wallet) before continuing. In essence, the marketplace has a read-only mode for the public – full functionality (like minting or buying agents) is gated behind authentication. This provides transparency about the product while protecting actual transactions.
	•	Login/Signup (/login, /signup): These pages allow users to authenticate. Signup might be available only to invited users during a closed beta, or it could be open registration if the platform is public. If sign-ups are restricted, the signup page might effectively be a “Join Waitlist” form, whereas authorized users (with an invite code or after waitlist approval) can create their account. The login page accepts existing members’ credentials. Social or web3 login options might also be available (for instance, “Login with Wallet” could be present – if a user connects a wallet that holds a Harmonix credential NFT or uses a token-based auth, it might log them in directly).

Logged-Out Experience Summary: In guest mode, users mainly see the polished marketing content and a teaser of the agent marketplace. They experience Harmonix’s brand style – dark elegant backgrounds with Deep Forest Green and Deep Space Black tones, contrasted by Warm Gold highlights on interactive elements – but functional pages are limited. All paths funnel toward conversion: either sign up for the waitlist/demo or log in to use the platform. This ensures no confusion for new visitors: anything beyond browsing info requires becoming a member, at which point the richer “app” part of the ecosystem opens up.

Authenticated (Logged-In) Pages and User Dashboard

Once logged in (as a Harmonix Member), the user enters the private web app experience. The navigation expands to include the dashboard and other app sections. The logged-in UI maintains the same harmonious style but also introduces more interactive components (charts, chat widgets, etc.) on a personalized dashboard.
	•	Dashboard (/dashboard): The landing page after login – a personalized User Dashboard. Here the user might see a welcome message (possibly from the Soul Brain AI), an overview of their “digital team” of agents, and any important alerts or stats. For example, the dashboard could show which agents the user has active, their performance stats or usage (if applicable), and prompts for next steps (“Connect a data source” or “Try chatting with your AI assistant”). The design is clean and uncluttered, aligned with the brand voice of being bold, clean, and soulful with no fluff ￼. Key components likely include:
	•	Soul Brain widget: prominently on the dashboard (more on Soul Brain below), inviting the user to ask questions or get assistance.
	•	Agent summary: a panel or carousel showing the user’s owned agents (if any) – e.g. their avatars, status (active/inactive), and quick actions like “configure” or “train”.
	•	Quick links: tiles or buttons to core sections (Marketplace, My Agents, Settings, etc.), ensuring frictionless navigation. For instance, a “+ Mint New Agent” button if the user has creator privileges, or a “Browse Marketplace” button if they have none yet.
	•	Possibly notifications or onboarding tips for new users (to guide them through connecting their first agent or integration).
	•	Soul Brain (AI Assistant) – Chat Interface: While not a page per se (it may be accessible globally via a chat icon or as part of the dashboard), the Soul Brain is a core UX element. When a user engages with Soul Brain (say by clicking a “Chat with Soul” button or the floating assistant icon), a chat panel or page opens. Here, the AI greets the user by name and context, often using details from the user’s profile (“Welcome back, Alex! How can I help with your real estate leads today?”). Soul Brain is designed to personalize responses based on the user’s industry and tools. For example, if the user indicated their industry as Real Estate during onboarding, Soul Brain’s tone and examples will align with real estate scenarios. If the user connected specific tools (e.g. their Google Calendar or CRM), Soul Brain can pull information or perform actions with those via integrated APIs. (E.g. the user might ask, “Soul, how many new leads did we get this week?” and if their CRM is connected, Soul Brain will retrieve that info; if not, it will politely explain it needs CRM access and guide the user to connect it in Integrations). This is part of the **“self-healing” UX – the assistant proactively guides users to fix gaps, like missing integrations, rather than just showing errors.)
Soul Brain supports multi-modal interaction. The user can type queries as with any chatbot, but there is also voice interaction support. A microphone button allows the user to speak their question; the AI will then process it (using speech-to-text under the hood) and respond. The response can be delivered as text and (if the user enables) via voice output using text-to-speech. This means a user could literally talk to the platform’s “brain” and get spoken answers – useful for hands-free scenarios or accessibility. The voice persona of Soul Brain would align with Harmonix’s brand – likely calm, confident, and insightful in tone. If the user’s device lacks a microphone or if they prefer not to use voice, the feature is optional, falling back to text chat seamlessly.
Fallback if No Integration/API: Soul Brain is designed to never hit a dead-end. If a user asks something that normally requires an integration the user hasn’t set up (e.g. “Schedule a client call for me” but no calendar is connected), Soul Brain will not simply say “error” – instead it will respond helpfully: “I’d be happy to do that, but I don’t have access to your calendar yet. Let’s connect your Calendar in Integrations, or I can create a reminder for you in the meantime.” This way, the user is informed of what’s missing and how to fix it (linking directly to the Integrations settings tab), and possibly given a partial solution (a reminder note) so they still feel assisted. This intelligent fallback ensures no frustrating dead-ends when using the AI assistant.
	•	Marketplace (Full) (/marketplace – logged-in view): The agent Marketplace for logged-in users is similar in layout to the public browsing version, but with full functionality enabled. Users can browse all agent cards by category, search, and view details just like guests, with added capabilities:
	•	A logged-in user can directly purchase or activate an agent from the detail view. The UI will show a prominent “Buy” or “Activate Agent” button on each agent’s page. It might also show pricing (possibly in tokens or credits, e.g. an ETH or stablecoin price if using crypto). On clicking buy, the app will initiate the wallet connection flow (if not already connected) and then the purchase transaction (described in Wallet Integration below).
	•	If the user already owns an agent (for example, if they obtained it through a promotion or previous purchase), the marketplace could indicate “Owned” or “In Your Team” on that agent, and perhaps allow re-configuring or upgrading it instead of buying again.
	•	Users with the Agent Creator role will also see options to “Mint Your Own Agent” or “Sell on Marketplace”. This might appear as a button on the marketplace page (like a “Create Agent” call-to-action) or as a separate section/tab within the marketplace for creators.
The marketplace is inherently gamified and collectible in nature. Each agent is not just a line item – it’s presented as a rich Agent Card as mentioned, often with dual sides (a visual avatar front, and a descriptive back). This approach “makes the invisible visible” – users get to collect their AI agents like one would collect Pokémon or Yu-Gi-Oh! cards ￼ ￼. The card back might even display an NFT serial number and an experience meter (if agents level up with usage) ￼. Harmonix leverages this to drive engagement: agents have story and status, not just utility. The marketplace may also feature limited-edition agent drops, bundles, or promotions (“Buy 3 agents, get 1 free consultation” etc. as per gamification ideas ￼).
	•	My Agents (/my-agents or part of dashboard): A section (page or dashboard module) listing all AI agents the user currently owns or has activated. This is essentially the user’s “AI team roster.” Each agent card the user owns is shown here with its current status (active, in training, etc.), usage stats (maybe “tasks done today” or “level XP”), and management options. For example, clicking an agent might allow the user to configure that agent’s settings or view detailed analytics. From My Agents, a user could also retire an agent (disable it), or access upgrade options if available (for instance, if an agent offers add-on modules or an upgrade to a newer version). If the user has no agents yet, this page will encourage them to visit the Marketplace to add one, possibly with a friendly note from Soul Brain or a link to the Marketplace.
	•	Mint/Create Agent (/create or /mint): This page (visible only to users with the Agent Creator capability) allows a user to create a new AI agent and mint it as an NFT to the marketplace. The flow for agent creation might look like a multi-step form or wizard:
	1.	Define Agent Basics: The creator enters the agent’s name, chooses its category/type (e.g. Sales Agent, Support Agent), and writes a description or selects a personality/archetype for the agent. They may also upload an avatar image or choose an illustrated character that represents the agent.
	2.	Configure Abilities: Here the creator sets what this agent does. This could involve selecting from predefined skill modules (like “can schedule calendar events”, “can send emails via Gmail”, etc.) or inputting a custom prompt/workflow if advanced. Essentially, this is where the agent’s “brain” is defined – possibly by composing smaller AI skills or linking APIs. (In a simplified MVP, it might just be a form to enter the core prompt or rules for the agent’s GPT-based behavior.)
	3.	Set Pricing & License: If the intent is to list it on the marketplace for others, the creator could set a price (in crypto or credits) or choose licensing terms. If it’s for personal use only, this step might be skipped or set to private.
	4.	Mint NFT: Once the agent’s details are filled, the creator hits a “Mint Agent” button. This triggers the blockchain transaction to mint a new NFT representing that agent card (with its metadata: name, image, attributes, etc.). The user will be prompted by their wallet (e.g. MetaMask) to confirm the mint transaction. After confirmation, the new Agent NFT is created. The agent now appears in the creator’s My Agents list and, if it was listed for sale, appears publicly in the Marketplace with the specified price. (If there’s an approval process, the agent might be in a pending state for admin review before going public.)
Throughout the create/mint flow, the user must be logged in and have a connected wallet (since minting writes to blockchain). If they haven’t connected one yet, the form will prompt them to do so before the final step. The UI provides guidance for any errors (e.g. if minting fails due to gas fees, it will catch that and inform the user to try again or check their wallet balance, rather than just failing silently). For non-crypto-savvy creators, the platform’s native wallet fallback can handle the mint (custodially mint the NFT for them), so even creators not deeply familiar with blockchain can participate in the marketplace.
	•	Settings (/settings) – Profile & Account: A hub for user account management, typically broken into multiple tabs or sub-sections. In Harmonix, Settings is comprehensive, covering personal info, preferences, billing, integrations, and more. (Each of these might be a sub-path like /settings/profile, but they are often just tabs on one page for UX simplicity.) The key tabs include:
	•	Profile: Basic user profile info and security. Users can update their name, email, profile photo, and password here. They might also set a display name or company name (if relevant for team context). If the platform uses the Soul Brain personalization, this is where industry and role info might be stored – e.g. a field for “Industry” that was set at signup, which Soul Brain uses to tailor responses. Profile also could include options like changing the UI theme (dark/light mode) if offered.
	•	Notifications: Manage how the user receives notifications. The user can toggle email notifications, SMS alerts (if phone connected), or in-app notification settings for various events (for example: when an agent completes a task, when a team member joins, when a new agent type is released on the marketplace, etc.). The design here is likely checkboxes or switches per notification type, in line with modern UX. Default settings (like critical alerts always on email) might be enforced, but generally user has control to reduce noise.
	•	Billing: Information on the user’s current plan and payment details. If Harmonix is a subscription service, this tab shows the user’s plan tier, renewal date, and usage quotas (e.g. number of agents allowed, API call limits, etc.). It also lets them update their credit card or crypto payment method. They can view billing history (invoices, receipts) and upgrade or downgrade their plan. For instance, a Member might see an option to upgrade to a Team or Creator plan here if those are paid tiers. This page is usually visible only to the account owner; invited team members might not see Billing.
	•	Integrations: Crucial for connecting external tools. This tab lists all the third-party integrations Harmonix supports (CRM systems, calendars, email services, project management tools, etc.). The user can connect or disconnect each one. For example, there might be a “Connect Google Calendar” button – clicking it begins an OAuth flow to link the user’s Google account. Once connected, it might show status or allow disconnecting. Similarly, “Connect MetaMask” or “WalletConnect” might appear here as part of wallet integration if the user wants to re-link or use a different wallet. If some integrations are only available on higher plans, the UI might indicate that (with an “Upgrade required” label). The Integrations page aims for a seamless onboarding – likely each integration has a short description and a one-click connect process. In case an API key is needed (for something like a custom API), the user can paste it here too. Any integration errors (wrong credentials, revoked access) would be highlighted with instructions to re-connect – again reflecting the self-healing UX philosophy.
	•	Agent Management: (Visible to Agent Creators or Admins) This tab is for users who create or manage AI agents themselves. It shows a list of agents the user has created (similar to My Agents, but focused on management settings rather than usage). For each created agent, the user might see controls to update its description, adjust pricing or availability (e.g. temporarily unlist it from marketplace or issue an update). If an agent is published to the marketplace, stats like number of times purchased by others or ratings might be displayed. Creators can also see if there are any pending approvals (if the platform reviews user-submitted agents). Essentially this is the “dashboard” for a creator to maintain their products. If the user is not an agent creator, this tab might be hidden entirely.
	•	Team Access: (Visible if the account is a Team/Organization or for enterprise plans) This tab deals with managing sub-users and permissions. Here an account owner or team admin can invite team members by email, assign them roles, or remove them. For example, a company using Harmonix might have multiple team members who need access – the owner would use this section to send invites. Each team member could be assigned a role like Member (default access) or perhaps custom roles if supported (maybe some team members can only view agents, others can edit, etc.). The Team Access page would list all current members, their role, and invitation status (for pending invites). It likely provides an easy way to resend invites or to revoke access. If the Team concept is simply an upper-tier multi-seat license, this tab ensures page visibility changes based on role – e.g., only the Team Owner sees billing; regular team members might not. In a collaborative scenario, the Team settings ensure everyone has the right level of access to pages and data.
Every Settings page is designed with clarity. Even though there are many tabs, the interface uses a consistent layout and the Harmonix visual style, so users don’t get lost. The color scheme remains consistent (e.g., form fields on a Soft Cloud light background over a deep dark UI, with gold or teal accents for active elements) to maintain brand continuity. There are no dead-end interactions – for instance, after updating any setting, the user gets feedback (like a success message, possibly with a subtle “harmonic” animation) to confirm the change, keeping the experience smooth.
	•	Admin Panel (/admin – restricted): A special area only accessible to Harmonix staff or platform administrators (users with the Admin role). This section is not visible to normal users at all. In the Admin Panel, designated admins can oversee the entire platform’s operation:
	•	User Management (/admin/users): A page listing all user accounts, with tools to search, filter, and manage them. Admins can view user profiles, their roles (e.g. upgrade a member to creator or team status, or revoke access), and maybe usage metrics. If needed, admins can manually approve new sign-ups (in a waitlist scenario) by toggling their status from pending to active. They can also handle any reports or issues with user accounts here.
	•	Agent Moderation (/admin/agents): A page to review and manage the agents listed on the marketplace. Admins might see a queue of newly minted agents from users and approve or reject them (ensuring quality and compliance with guidelines). They can also remove any agent listing that violates terms or is found problematic. Each agent entry could show details like its creator, how many times it’s been purchased, ratings, etc., giving admins oversight. This ensures the marketplace remains healthy and curated.
	•	Analytics & System Settings: There could be additional admin pages for platform-wide analytics (user growth, transaction volumes, etc.) and configuration (like adjusting feature flags, sending announcements to all users, etc.), though these are more backend oriented. From a sitemap perspective, it’s enough to note that admin routes exist and are gated by admin role. Attempting to access them as a non-admin would either not even show the route or result in a 403 Unauthorized page.

Logged-In Experience Summary: Authenticated users gain access to the rich “operating system” of Harmonix – a dashboard-centric app where they can deploy and manage AI agents. The UI adapts based on role: a basic Member sees core pages (Dashboard, Marketplace, their Agents, Settings), an Agent Creator sees additional creation tools, a Team user sees collaborative features, and an Admin sees the oversight panel. Navigation is intuitive and avoids any clutter – for instance, if a user doesn’t have admin rights or agent-creation rights, those sections simply don’t appear, keeping their interface clean. The design remains consistent: Deep Space Black backgrounds for depth, Warm Gold accents for interactive highlights (e.g. the primary buttons like “Buy” or “Save” are gold for prominence), and perhaps Deep Forest Green or Ethereal Teal accents in illustrations or secondary buttons to evoke innovation and growth ￼ ￼. The result is an experience where a user intuitively feels guided and “in alignment” as they navigate, fulfilling the brand’s promise of clarity and legacy.

Marketplace User Flow (Browsing, Purchasing & Minting Agents)

The Marketplace UX flow in Harmonix is designed to be smooth for both buyers and creators, integrating necessary logins and wallet steps only at the points they’re needed. Below is a step-by-step of typical user actions:

For Browsing & Purchasing Agents (Buyer perspective):
	1.	Browse Listings: The user (guest or logged-in) browses the agent marketplace (/marketplace). Agents are categorized (e.g. Marketing, Sales, Operations, etc.), and the user can filter or search. Each listing is shown as an Agent Card with a thumbnail image and key info. The design encourages exploration – for example, hovering an agent card might flip it to show a quick stat or the agent’s “unique power.” This gamified browsing is meant to spark curiosity (aligning with the emotional connection and story around each agent ￼ ￼).
	2.	View Agent Details: Clicking a specific agent opens its detail page (/marketplace/{agent-id}) where the user sees a full description. This includes the agent’s avatar artwork, a backstory or personality blurb, its functional capabilities (what tasks it can automate or decisions it can handle), and technical details if any (like which tools it integrates with). It also shows price and any available quantity or edition info (if NFTs are limited editions). There may be user reviews/ratings visible (future enhancement ￼ ￼), but at MVP it might just be descriptive. A logged-out user will also see a “Log in to purchase” overlay or disabled button, whereas a logged-in user sees an active “Purchase” or “Deploy” button.
	3.	Initiate Purchase (Login if needed): When the user decides to buy, they click the purchase button. If the user is not logged in, this triggers the login/signup prompt first (because only members can own agents). The user will need to authenticate (and possibly confirm email, etc. if first time) and then will be returned to this agent page to continue. If the user is logged in but has not connected a wallet yet, at this point the system will prompt them to connect one (since the purchase involves a blockchain transaction). A modal appears with wallet options (MetaMask, WalletConnect, or create a Harmonix wallet). The user chooses their method and connects. Once the wallet is connected and the user is authenticated, the purchase flow continues.
	4.	Connect Wallet (if not already): Harmonix supports multiple wallet connection strategies:
	•	MetaMask: If the user has MetaMask installed (web extension or in-app browser), clicking the connect option will prompt MetaMask to connect to Harmonix. The UI might detect MetaMask automatically and show “Connect MetaMask” as the first choice. Upon clicking, the MetaMask extension pops up asking for permission to connect the user’s address. The user approves, and now their Ethereum (or applicable chain) address is linked to their Harmonix account. A small wallet icon in the UI might turn green or show the shortened address to indicate success.
	•	WalletConnect: If the user is on mobile or prefers a different wallet (Trust Wallet, etc.), they can choose WalletConnect. This opens a QR code (or a deep link) that the user scans with their mobile wallet app. Once scanned and approved on their phone, the Harmonix web app is connected to that wallet. This is the fallback for any wallet – ensuring broad compatibility beyond MetaMask.
	•	Harmonix Native Wallet: For users unfamiliar with crypto or who don’t have an external wallet, Harmonix provides an easy custodial wallet solution. This might be as simple as “Create a Harmonix Wallet” button – which in the background generates a key (potentially secured by the user’s login credentials or a separate passphrase). The user doesn’t have to handle seed phrases; the platform secures it for them. It could also use a service like Magic.link or Web3Auth to tie the wallet to their email/social login. The key point is that no user is blocked from purchasing due to lack of a wallet – there’s always a convenient fallback so they can still acquire agents (the assets would be held in trust by the platform until they export to a real wallet, if ever). This lowers the barrier for non-crypto users, aligning with a “frictionless onboarding” philosophy.
The wallet connection step is only required once. Harmonix likely remembers the connection (via a signed message or linking the wallet address in the user’s account). For subsequent purchases, if the wallet is still connected, it goes straight to the transaction confirmation.
	5.	Confirm Purchase Transaction: After choosing the wallet, the user confirms they want to buy the agent. A summary dialog may appear showing the agent name, price, and any fees (e.g. “This agent costs 0.05 ETH”). Upon confirming, the user’s wallet (MetaMask etc.) will pop up a transaction confirmation with the details (smart contract address, gas fee, etc.). The user approves it, and the transaction is submitted on-chain. A loading indicator in the UI shows progress (“Transaction pending…confirming on blockchain”). Once the network confirms, the UI will show a success message (“Agent acquired! [Agent Name] is now in your team.”). The NFT representing the agent is now transferred to the user’s wallet (or created in their custodial wallet), and the platform gives the user access to deploy and use that agent.
	6.	Post-Purchase Activation: Immediately after purchase, the platform might guide the user to activate or configure the agent. For instance, it could navigate to a setup page for that agent, where the user can link it with their specific data or preferences (e.g. if it’s a CRM Assistant agent, perhaps ask which CRM it should tie into – maybe it leverages the Integrations settings). If no additional setup is required, the agent might be active by default, and the user can see it in My Agents on their dashboard. In any case, the agent’s card likely gets a visual update (like a status indicator “Active” or some animation to celebrate the new addition). This positive reinforcement ties back to the gamified design – collecting an agent should feel rewarding, akin to leveling up in a game ￼ ￼.

Throughout the purchase flow, the UX is kept intuitive and secure. If at any point the user cancels (e.g. closes the wallet popup or the transaction is rejected), the app catches that and shows a non-intimidating message like “Purchase canceled” or “Looks like you didn’t approve the transaction. Need help?” – possibly even invoking Soul Brain to offer assistance (e.g. explaining how to adjust gas fees if it failed due to low gas). This is part of UX self-healing – anticipating points of failure and providing guidance rather than leaving the user stuck or confused.

For Minting Your Own Agent (Creator perspective):
If a user has the role or permission to create agents, the flow to mint an agent involves some extra steps (as outlined in the Create Agent page earlier). To summarize the UX flow:
	1.	Access the Creation Interface: The user clicks on “Mint New Agent” (could be a button on their dashboard or marketplace). If the user is not yet an approved creator (for example, maybe this feature is restricted or behind a plan), they may be taken to an upgrade page or an application form first. Assuming they have access, they reach the agent creation form (/create).
	2.	Design the Agent: The interface likely breaks the process into UI sections (as described before: Basics, Abilities, Pricing). The UX here might include helpful templates – e.g., a user could choose “Start from Template” to use a base Sales Agent structure and just customize it. Harmonix’s design board principles ensure even a complex form is not overwhelming: perhaps using a stepper (multi-step wizard) with a progress bar. The form might also be aided by the Soul Brain or another assistant: for example, as the user fills out the agent’s description, an AI helper could suggest improvements (“Want me to generate a catchy bio for your agent?”).
	3.	Preview & Mint: Before finalizing, the user likely gets a preview of how their Agent Card will look to others. This is where they can double-check everything. Once satisfied, they hit Mint. Now, similar to buying, if their wallet isn’t connected, they’ll be prompted to connect (creators definitely need a wallet since they will be the one minting the NFT). The wallet integration logic is the same as above: use MetaMask or alternatives, or let Harmonix create a wallet for them.
	4.	Blockchain Transaction – Minting: Upon clicking confirm, a smart contract call is made to mint the new agent NFT (which might also register it in the marketplace contract). The user signs this transaction in their wallet. The UI shows progress. If there’s a fee for minting (gas fee), the user pays it here. After confirmation, the new Agent NFT is created in their wallet (they are the owner and possibly the issuer).
	5.	Listing & Approval: If the user intended to sell this agent, the platform will list it on the marketplace. Possibly the system sets the first owner as the seller with the price given. If the platform requires admin approval for new agents (to ensure quality or no malicious content), the agent might be listed as “Pending” and not visible to the public until an admin approves. The UX will reflect that: e.g. “Your agent has been submitted and is under review. It will appear in the marketplace once approved.” If no approval is needed or it’s auto-approved, it could appear immediately.
	6.	Feedback to Creator: The interface notifies the user that their agent is successfully minted. It now shows up in their My Agents list, marked perhaps as “Created by You”. They can click it to see how it appears publicly. If it’s listed, they might also be able to see if anyone purchases it eventually (there could be a notification or a sales dashboard for creators – maybe not in MVP, but logically to be added).

The marketplace thus has a two-way flow: consumption (buying agents) and creation (minting agents). Harmonix handles both in a unified ecosystem, with the necessary guardrails (login, wallet connect, role permissions) integrated at the points they are needed. Notably, the system’s role-based access controls ensure that only authorized users see the “mint agent” capabilities ￼. This prevents confusion (a normal user isn’t tempted to click “Create Agent” if they shouldn’t) and keeps the UI tailored to the user’s journey.

Wallet Integration & Fallback Logic

Harmonix embraces web3 technology (NFTs for agents) while striving to be user-friendly for non-crypto natives. The platform’s wallet integration strategy reflects this balance:
	•	MetaMask (Browser Wallet): As the primary method, Harmonix detects and integrates with MetaMask seamlessly. When a logged-in user initiates a blockchain action (buying or minting an agent), the site will check for MetaMask. If present, it triggers a connect request. The UI provides context like “Connecting to your MetaMask wallet…”. After the first connection, the user’s Ethereum address might be displayed in the navbar (partial address or user’s ENS, if applicable) to confirm they’re connected. MetaMask is popular and reliable, so it’s prioritized for those who have it.
	•	WalletConnect (Mobile & Alternatives): For users on mobile devices or using wallets other than MetaMask, WalletConnect is offered. Edge Cases & UX Self‑Healing Mechanisms

No platform is complete without considering edge cases – those not-so-happy paths where users might stray into unknown territory or something goes wrong. Harmonix is built to handle these situations gracefully, employing a “self-healing” UX approach to gently guide users back on track and prevent frustration. Here are key edge cases and how the system deals with them:
	•	Broken Link / 404 Page: If a user somehow navigates to a non-existent route (say, /agent/12345 that doesn’t exist or an old URL), Harmonix provides a custom 404 error page that is on-brand and helpful. Instead of a generic “Not Found”, the page likely has a message like “Oops, that page is in harmony not found.” (maybe a bit of playful wording tying into the brand). It might feature an illustration of Soul Brain looking around confused or a broken circuit that magically reassembles (showing self-healing visually). Importantly, the 404 page offers suggestions: “You can go back to the Dashboard, visit the Marketplace, or ask Soul Brain for help.” Possibly a search bar or link to FAQ is included too. This ensures the dead-end is actually an opportunity to re-engage. Additionally, the system might log the broken link behind the scenes so the team can see if certain URLs are commonly hit (and perhaps set up redirects in the future).
	•	Unbuilt / Coming Soon Pages: During iterative development, there may be menu items or features that are mentioned but not yet available. Instead of leaving them inaccessible or throwing errors, Harmonix handles them with “Coming Soon” guards. For example, if “Analytics” is a menu item for a future phase, clicking it as a user might show a page that says “Analytics are coming soon! We’re working hard to bring you this feature. Stay tuned.” along with maybe an invite to join a beta or an option to be notified. The styling of such pages is consistent (maybe a placeholder graphic and the standard nav still visible so it doesn’t feel jarring). By doing this, users are informed that the feature is recognized and on the roadmap, rather than thinking something is broken. In some cases, the app might hide these features entirely until they’re ready (feature flags), which is even better to avoid confusion. But if a placeholder is shown, it’s never a dead blank page – always a friendly explanation and often a call-to-action (even if that action is simply “Learn more about our roadmap” with a link to a blog or “vote on this feature” if a feedback forum exists).
	•	Unauthorized Access (Permission Denied): When a logged-in user tries to access something they shouldn’t (maybe by guessing a URL or via stale UI), the system will protect the content and inform the user appropriately:
	•	If a Member tries to access an Admin page, they might get a styled 403 page saying “You don’t have permission to view this page.” Possibly Soul Brain even pops up to say “It looks like you tried to access an admin feature. If you think you should have access, contact support.” (But generally, the UI would not expose admin links at all to non-admins).
	•	If a user without the Agent Creator role goes to /create, instead of showing the form, they could see a message: “This section is for Agent Creators. Interested in creating your own AI agents? Upgrade your plan or apply for access.” with a button leading to upgrade or info. This turns a denial into a potential upsell or educational moment.
	•	If a team member tries to do an action only the team owner can (like change billing), the app should either hide that control or show a tooltip “Only the account owner can do this.” If they still reach the page, a read-only view might be presented (for example, a team member could view the billing info but all fields are disabled, with a note).
The consistent theme is: inform the user and offer a path forward. Never just a cryptic “Forbidden” or, worse, a blank page. The messaging stays polite and possibly even empathetic: acknowledging the user’s intent and clarifying the restriction.
	•	Form Errors and Validation: A subtle but important edge case category. If a user inputs something invalid (like an improperly formatted email or a password that doesn’t meet criteria), the form will not just highlight the field in red, but also display a clear message next to it (e.g., “Please enter a valid email address”). Harmonix’s style might even use the brand colors for these messages (perhaps a touch of Warm Gold or Teal instead of harsh red, to keep with the palette, though red could be introduced solely for errors if needed for universal convention). The error messages likely have a friendly tone, e.g., “Oops, that password is too short. Try at least 8 characters with a number.” This falls under UX self-healing by guiding the user to correct mistakes without frustration.
	•	System Errors & Failures: Sometimes the unexpected happens – maybe the AI service is down, or an integration’s API is failing, etc. In such cases, rather than throwing a technical error, Harmonix will catch it and provide feedback. For instance, if Soul Brain cannot get a response (OpenAI API downtime, say), the chat might say “Sorry, I’m feeling a bit cloudy and can’t think straight at the moment. Let’s try again in a minute.” (keeping it light) and log this issue for tech team. Or if a user tries to save settings but the server doesn’t respond, the UI might show a notification “Network issue – we couldn’t save your changes yet. Retrying…” and automatically attempt to retry a couple of times. Many modern apps implement background retries and only alert the user if something truly can’t go through after several attempts. Harmonix, aiming for a polished experience, would do the same: minor hiccups are often resolved without user intervention (self-healing), and only if an action definitively fails will the user be alerted with an error message that includes next steps (“If this persists, contact support or try again later.”).
	•	Navigation & Dead-ends: The site map is constructed to avoid dead-ends in navigation. Every page either concludes with a suggested next step or provides navigation options to go elsewhere:
	•	After someone signs up, they’re taken straight to an onboarding flow or dashboard (not left wondering what to do).
	•	After purchasing an agent, perhaps a modal suggests “Now configure this agent” with a button to its settings, or “Go to Dashboard” to see it in action.
	•	If a user deletes something (say removes an agent), the UI might show an empty state with suggestions rather than just an empty table. For example, “You have no agents now. Visit the Marketplace to add one or use Soul Brain for guidance.”
	•	The app likely also has a help center or support link (maybe a “Help?” button in a corner or within the user menu). If a user is truly lost or an edge scenario wasn’t accounted for, they can always click help to either chat with a human or view FAQs.
	•	Self-Healing UX Philosophy: As a general principle, Harmonix tries to anticipate possible missteps and correct them proactively:
	•	If a user seems to idle on a page without completing an action (maybe they opened the Create Agent form but didn’t finish), Soul Brain could gently ping: “Need any help creating your agent?” offering tips.
	•	If the system detects a broken link that multiple users hit, maybe the next update introduces a redirect or a fix without users even having to report it (an example of the team using self-healing in development cycle).
	•	The design likely uses a lot of preventative measures, like disabling buttons until required fields are filled, etc., to minimize actual errors.

The outcome of all this attention to edge cases is that users feel supported, not frustrated, even when something goes wrong. They’re either quietly guided back to the happy path or at least informed in a kind, useful way. Harmonix recognizes that the experience doesn’t end at ideal usage; it extends to how issues are handled. This resilience in UX builds trust – users know that if they make a mistake or if something breaks, the system will help them recover quickly. In a domain as complex as AI + blockchain, this is crucial to keep users from feeling overwhelmed. So whether it’s a simple 404 or a complex transaction failure, Harmonix has a plan for it, reinforcing the platform’s polished, “no dead-ends” design philosophy.
